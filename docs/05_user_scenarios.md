# 5. Пользовательские сценарии

## SC-01: Регистрация студента

**Актор**: незарегистрированный студент СГТУ

1. Пользователь открывает главную страницу, нажимает «Регистрация».
2. Заполняет форму: ФИО, номер студенческого билета, email, пароль, подтверждение пароля.
3. Система сверяет ФИО + номер студенческого билета с базой данных верификации.
4. Данные совпали → аккаунт создаётся с ролью `student`, начальный рейтинг = 50 баллов.
5. Система перенаправляет на страницу профиля с предложением заполнить дополнительные данные (аватар, Telegram, направления интересов).
6. Студент попадает на главную — система готова к использованию.

**Результат**: аккаунт создан, студент авторизован.

---

## SC-02: Ошибка при верификации

**Актор**: незарегистрированный пользователь

1. Пользователь заполняет форму регистрации.
2. Система не находит совпадения ФИО + номер студенческого билета в БД.
3. Система показывает сообщение: «Данные не найдены. Проверьте правильность ФИО и номера студенческого билета. Если данные верны — обратитесь в поддержку.»
4. Под сообщением — кнопка «Написать в поддержку» со ссылкой на Telegram-бот.
5. Пользователь переходит в Telegram-бот, описывает проблему.
6. Оператор проверяет данные и при необходимости добавляет запись в БД верификации или заводит аккаунт вручную.

**Результат**: пользователь направлен в поддержку, проблема решается вручную.

---

## SC-03: Регистрация школьника / гостя

**Актор**: школьник или внешний гость

1. На странице регистрации пользователь видит текст: «Для школьников и гостей: обратитесь к нашему Telegram-боту для получения доступа.»
2. Пользователь переходит в Telegram-бот.
3. Бот собирает данные: ФИО, возраст, контакт, цель визита.
4. Администратор видит заявку в админ-панели (или в боте).
5. Администратор создаёт аккаунт с ролью `guest` и отправляет логин/пароль через бота.
6. Школьник/гость входит на платформу — видит расписание, направления, новости, карту. Бронирование и рейтинг недоступны.

**Результат**: аккаунт с ограниченным доступом создан.

---

## SC-04: Просмотр расписания

**Актор**: любой авторизованный пользователь

1. Пользователь переходит в раздел «Расписание».
2. По умолчанию показано расписание на текущий день для всех направлений.
3. Пользователь выбирает фильтры: направление, дата, локация.
4. Система показывает таймлайн слотов с цветовой индикацией: свободен (зелёный), частично занят (жёлтый), занят (красный).
5. Клик на слот открывает карточку: время, направление, ресурс, локация, текущие участники, кнопка «Записаться» (для студентов).

**Результат**: пользователь видит актуальное расписание.

---

## SC-05: Индивидуальная бронь

**Актор**: студент

1. Студент в расписании находит свободный слот нужного направления.
2. Нажимает «Записаться».
3. Система проверяет:
   - рейтинг студента ≥ порога (не заблокирован);
   - не превышен лимит бронирований на неделю;
   - слот не заполнен.
4. Все проверки пройдены → бронь создана.
5. Студент видит подтверждение: «Бронь подтверждена. PlayStation, 15:00–16:00, ауд. 301».
6. Бронь появляется в разделе «Мои бронирования» в профиле.
7. Студент получает уведомление (in-app + Telegram).

**Результат**: слот забронирован, студент уведомлён.

---

## SC-06: Командная бронь

**Актор**: капитан команды (студент)

1. Студент переходит в раздел «Команды» → «Создать команду».
2. Указывает название команды и направление (например, «Лазертаг»).
3. Приглашает участников по username или из списка друзей.
4. Приглашённые получают уведомление и принимают/отклоняют приглашение.
5. Когда команда собрана (минимум для лазертага — 4 человека), капитан переходит в расписание.
6. Выбирает слот «Лазертаг» → нажимает «Записать команду».
7. Система проверяет: рейтинг всех участников, лимиты, вместимость слота (8–10 человек).
8. Бронь создана для всей команды. Каждый участник получает уведомление.

**Результат**: командный слот забронирован, все участники уведомлены.

---

## SC-07: Отмена брони

**Актор**: студент

1. Студент открывает «Мои бронирования» в профиле.
2. Находит предстоящую бронь, нажимает «Отменить».
3. Система проверяет: до начала слота > 24 часов?
   - **Да** → бронь отменяется без последствий. Слот становится свободным.
   - **Нет** → система показывает: «Отмена невозможна менее чем за 24 часа до начала. Обратитесь к тренеру.»
4. При успешной отмене — уведомление: «Бронь отменена. Слот PlayStation 15:00–16:00 освобождён.»

**Результат**: бронь отменена (или отказ с объяснением).

---

## SC-08: Подтверждение посещения тренером

**Актор**: тренер

1. Тренер открывает раздел «Мои занятия» → выбирает текущий/прошедший слот.
2. Видит список записавшихся студентов.
3. Для каждого студента отмечает: «Присутствовал» или «Не явился».
4. Нажимает «Сохранить».
5. Система:
   - присутствовавшим начисляет +10 баллов;
   - не явившимся снимает −20 баллов;
   - отправляет уведомления студентам об изменении рейтинга.
6. Данные записываются в историю посещений и журнал действий.

**Результат**: посещение зафиксировано, рейтинги обновлены.

---

## SC-09: Просмотр рейтинга / баллов

**Актор**: студент

1. Студент нажимает на свой рейтинг в шапке сайта (виджет с числом баллов).
2. Открывается страница «Рейтинг»:
   - текущий балл (крупно, с цветовой индикацией уровня);
   - текущий лимит бронирований;
   - лидерборд (топ-20 + позиция студента);
   - история изменений (дата, причина, ±баллы);
   - ссылка на правила.
3. Студент может открыть вкладку «Правила» — таблица с описанием всех начислений и списаний.

**Результат**: студент понимает свой рейтинг и как его улучшить.

---

## SC-10: Получение награды

**Актор**: студент

1. Студент переходит в раздел «Награды».
2. Видит каталог: карточки с фото, названием, стоимостью в баллах, остатком.
3. Выбирает награду (например, «Фирменная футболка CIFRA — 200 баллов»).
4. Нажимает «Получить».
5. Система проверяет: достаточно ли баллов? Есть ли в наличии?
   - **Да** → создаётся заявка на выдачу, баллы списываются. Статус: «Ожидает выдачи».
   - **Нет** → сообщение: «Недостаточно баллов» или «Награда закончилась».
6. Администратор видит заявку в админ-панели → подтверждает выдачу (физически отдаёт мерч).
7. Статус меняется на «Выдано». Студент получает уведомление.

**Результат**: баллы списаны, награда в процессе выдачи.

---

## SC-11: Просмотр материалов

**Актор**: любой авторизованный пользователь

1. Пользователь переходит в раздел «Материалы».
2. Видит список материалов с фильтрами: направление, тип (инструкция, видео, PDF, памятка).
3. Выбирает материал — открывается карточка:
   - для текста — рендерится на странице;
   - для PDF — встроенный просмотрщик + кнопка скачивания;
   - для видео — встроенный плеер;
   - для ссылки — открывается в новой вкладке.
4. Пользователь может вернуться к списку или перейти к следующему материалу.

**Результат**: пользователь получил нужную информацию.

---

## SC-12: Просмотр карты кампуса

**Актор**: любой авторизованный пользователь

1. Пользователь переходит в раздел «Карта».
2. Загружается 2D-схема кампуса с отмеченными точками активностей.
3. Пользователь может масштабировать и перемещать карту.
4. Клик на точку → всплывающее окно: название локации, направления, краткое описание.
5. В окне кнопка «Подробнее» → переход на страницу локации с расписанием и кнопкой «Забронировать».

**Результат**: пользователь нашёл нужную площадку и перешёл к бронированию.

---

## SC-13: Подача анкеты кандидата в ДКШ

**Актор**: студент

1. Студент переходит в профиль → вкладка «Кандидат ДКШ».
2. Видит форму анкеты:
   - О себе (текст, до 500 символов)
   - Навыки (теги из предустановленного списка + свободный ввод)
   - Интересы (теги)
   - Достижения (текстовые записи)
   - Направления (чекбоксы из каталога)
   - Опыт работы/наставничества (текст)
   - Контакты (Telegram, VK, телефон)
3. Заполняет и нажимает «Сохранить».
4. Анкета сохраняется со статусом «Активна» и становится видна администратору.
5. Студент может редактировать анкету в любой момент.

**Результат**: анкета создана, доступна администратору.

---

## SC-14: Работа администратора

**Актор**: администратор

### Типичный рабочий день:
1. Входит в админ-панель → видит дашборд:
   - активных пользователей за сегодня;
   - предстоящих бронирований;
   - неподтверждённых посещений;
   - заявок на выдачу наград;
   - новых заявок школьников/гостей.
2. Просматривает заявки школьников → одобряет/отклоняет.
3. Переходит в «Слоты» → создаёт расписание на следующую неделю (выбирает направление, ресурс, дни, время, длительность → система генерирует слоты).
4. Переходит в «Новости» → публикует анонс турнира.
5. Проверяет аналитику → видит, что загрузка дронов низкая → решает добавить открытые слоты.
6. Выгружает отчёт по посещаемости в Excel для руководства.

## SC-15: Публикация турнира

**Актор**: администратор

1. Переходит в «Новости» → «Создать анонс».
2. Заполняет:
   - Заголовок: «Турнир по CS2 — весенний кубок CIFRA»
   - Тип: анонс турнира
   - Направление: киберспорт
   - Дата и время проведения
   - Место (выбор из локаций)
   - Описание, правила участия, формат
   - Обложка (загрузка изображения)
3. Нажимает «Опубликовать».
4. Анонс появляется в ленте новостей и на главной странице.
5. Все пользователи получают уведомление о новом анонсе (если подписаны на направление).

**Результат**: анонс опубликован, пользователи уведомлены.

---

## SC-16: Публикация результатов турнира

**Актор**: администратор

1. После проведения турнира переходит в «Новости» → «Создать пост».
2. Заполняет:
   - Заголовок: «Итоги весеннего кубка CIFRA по CS2»
   - Тип: результат турнира
   - Связанный анонс (выбор из ранее опубликованных)
   - Текст с результатами, фото, комментарии
   - Список победителей (ФИО, команда, место)
3. Опционально: начисляет баллы победителям через интерфейс рейтинга.
4. Публикует пост.
5. Связанный анонс получает статус «Завершён» и ссылку на результаты.

**Результат**: результаты опубликованы, баллы начислены.
