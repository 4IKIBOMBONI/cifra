# 14. Техническое задание

## 1. Цель

Разработка веб-платформы «CIFRA» — внутреннего цифрового сервиса СГТУ для управления фиджитал-активностями университета. Платформа обеспечивает бронирование ресурсов, учёт посещаемости, геймифицированную мотивацию студентов и информирование о мероприятиях.

## 2. Область применения

- Фиджитал-центр СГТУ (Саратов)
- Направления на старте: киберспорт, лазертаг, дроны, PlayStation, компьютерные тренировочные места
- Расширяемость на любые секции и активности университета

## 3. Пользователи

### 3.1 Студент
- Основной пользователь платформы
- Верификация по ФИО + номер студенческого билета
- Полный доступ: бронирование, рейтинг, награды, команды, ДКШ

### 3.2 Школьник / гость
- Ограниченный доступ (просмотр расписания, новостей, направлений, карты)
- Заводится администратором через Telegram-бот

### 3.3 Тренер / организатор
- Подтверждение посещений
- Управление слотами своих направлений
- Начисление/снятие баллов за посещение

### 3.4 Администратор
- Полный доступ к управлению всеми сущностями платформы

## 4. Функциональные требования

### FR-01: Регистрация и авторизация
- FR-01.1: Регистрация студента с верификацией ФИО + номер студбилета по БД.
- FR-01.2: При несовпадении — сообщение об ошибке и ссылка на Telegram-бот поддержки.
- FR-01.3: Вход по email + пароль.
- FR-01.4: JWT-авторизация (access token 15 мин, refresh token 7 дней).
- FR-01.5: Восстановление пароля через email.
- FR-01.6: Ручное создание аккаунтов школьников/гостей администратором.

### FR-02: Профиль пользователя
- FR-02.1: Просмотр и редактирование профиля (аватар, ФИО, контакты).
- FR-02.2: Просмотр своих бронирований, рейтинга, истории.
- FR-02.3: Управление уведомлениями.

### FR-03: Направления
- FR-03.1: Каталог направлений с описанием, фото, иконками.
- FR-03.2: Настраиваемые параметры: вместимость, длительности слотов.
- FR-03.3: CRUD направлений (администратор).

### FR-04: Ресурсы и локации
- FR-04.1: Каталог ресурсов (оборудование, площадки, рабочие места).
- FR-04.2: Статусы ресурсов: активен, на обслуживании, выведен.
- FR-04.3: Привязка ресурсов к направлениям и локациям.
- FR-04.4: Каталог локаций с координатами для карты кампуса.

### FR-05: Бронирование
- FR-05.1: Расписание слотов с фильтрацией по направлению, дате, локации.
- FR-05.2: Представление: день (вертикальный список) и неделя (сетка).
- FR-05.3: Индивидуальное бронирование.
- FR-05.4: Командное бронирование.
- FR-05.5: Открытые слоты (запись любого студента).
- FR-05.6: Длительности: 30 мин, 1 час, 2 часа.
- FR-05.7: Отмена без штрафа за 24+ часов. Отмена менее чем за 24 часа заблокирована.
- FR-05.8: Подтверждение посещения тренером (присутствовал / не явился).
- FR-05.9: Проверка рейтинга и лимита бронирований перед записью.
- FR-05.10: Генерация слотов по расписанию (администратор/тренер).

### FR-06: Команды
- FR-06.1: Создание команды (название, направление).
- FR-06.2: Приглашение участников.
- FR-06.3: Принятие/отклонение приглашений.
- FR-06.4: Командное бронирование капитаном.

### FR-07: Рейтинг и баллы
- FR-07.1: Единая рейтинговая система (баллы = рейтинг в v1).
- FR-07.2: Начисление: посещение (+10), турнир (+20), достижение (+50), полезное действие (+5–30).
- FR-07.3: Снятие: неявка (−20), поздняя отмена (−10), нарушение (−30).
- FR-07.4: Лимиты: < 0 = блокировка, < 30 = 1 слот/нед, 30–70 = 3 слота/нед, 70+ = 5 слотов/нед.
- FR-07.5: Лидерборд (топ-20 + позиция пользователя).
- FR-07.6: История изменений с причинами.
- FR-07.7: Страница правил.
- FR-07.8: Уведомления при изменении рейтинга.
- FR-07.9: Ручная корректировка администратором.

### FR-08: Награды
- FR-08.1: Каталог наград (фото, описание, стоимость, остаток).
- FR-08.2: Запрос на получение (списание баллов).
- FR-08.3: Подтверждение выдачи администратором.
- FR-08.4: История начислений и списаний.
- FR-08.5: Управление каталогом и остатками (администратор).

### FR-09: Новости и турниры
- FR-09.1: Лента новостей с фильтрацией: новости, анонсы, результаты.
- FR-09.2: Публикация через админку (заголовок, текст, обложка, направление, теги).
- FR-09.3: Анонсы турниров с датой, местом, форматом.
- FR-09.4: Публикация результатов с привязкой к анонсу.

### FR-10: Обучающие материалы
- FR-10.1: Каталог с фильтрацией по направлению и типу.
- FR-10.2: Поддержка: текст, PDF, видео (YouTube/VK), ссылки.
- FR-10.3: Поиск по названию.
- FR-10.4: Управление через админку.

### FR-11: Карта кампуса
- FR-11.1: 2D SVG-схема кампуса.
- FR-11.2: Интерактивные маркеры точек активностей.
- FR-11.3: Попап с информацией о локации.
- FR-11.4: Переход к расписанию и бронированию.
- FR-11.5: Масштабирование и панорамирование.

### FR-12: Профиль кандидата ДКШ
- FR-12.1: Создание и редактирование анкеты (только студент).
- FR-12.2: Поля: о себе, навыки, интересы, достижения, направления, опыт, контакты.
- FR-12.3: Просмотр и фильтрация анкет (администратор).

### FR-13: Администрирование
- FR-13.1: Дашборд с ключевыми метриками.
- FR-13.2: CRUD всех основных сущностей.
- FR-13.3: Управление пользователями (создание, блокировка, смена роли).
- FR-13.4: Генерация слотов.
- FR-13.5: Публикация контента.
- FR-13.6: Управление рейтингом и наградами.

### FR-14: Аналитика
- FR-14.1: Метрики: пользователи, посещаемость, загрузка слотов, популярность направлений, неявки, награды, кандидаты ДКШ.
- FR-14.2: Графики динамики по периодам.
- FR-14.3: Выгрузка Excel (.xlsx) и PDF.

### FR-15: Уведомления
- FR-15.1: In-app уведомления (колокольчик с счётчиком).
- FR-15.2: Типы: бронирование, рейтинг, команды, награды, анонсы, системные.
- FR-15.3: Отметка «прочитано».
- FR-15.4: Telegram-уведомления для критичных событий.

### FR-16: Журнал действий
- FR-16.1: Логирование всех CUD-операций.
- FR-16.2: Фильтрация по пользователю, типу, дате.
- FR-16.3: Просмотр в админ-панели.
- FR-16.4: Append-only (записи не удаляются и не редактируются).

## 5. Нефункциональные требования

### NFR-01: Производительность
- Время отклика API: < 500 мс для 95% запросов.
- Время загрузки страницы: < 3 секунды на 3G.
- Поддержка до 500 одновременных пользователей.

### NFR-02: Доступность
- Uptime: 99% (допускается плановое обслуживание).
- Graceful degradation при недоступности Redis.

### NFR-03: Масштабируемость
- Горизонтальное масштабирование backend через Docker.
- Модульная архитектура для выделения микросервисов.

### NFR-04: Совместимость
- Браузеры: Chrome 90+, Firefox 90+, Safari 15+, Edge 90+.
- Мобильные: iOS Safari 15+, Android Chrome 90+.
- Разрешения: от 320px до 2560px.

## 6. Требования к безопасности

- SEC-01: Хеширование паролей (bcrypt, cost factor 12).
- SEC-02: JWT с коротким TTL (15 мин access, 7 дней refresh).
- SEC-03: Refresh token в httpOnly cookie.
- SEC-04: CORS — только разрешённые домены.
- SEC-05: Rate limiting на эндпоинтах аутентификации (5 попыток / минута).
- SEC-06: Валидация всех входных данных (Pydantic).
- SEC-07: Параметризованные SQL-запросы (SQLAlchemy ORM).
- SEC-08: Санитизация пользовательского HTML-контента.
- SEC-09: HTTPS (TLS 1.2+).
- SEC-10: Audit log всех административных действий.

## 7. Требования к UX/UI

- UI-01: Mobile-first адаптивный дизайн.
- UI-02: Геймифицированный интерфейс (рейтинг, бейджи, анимации).
- UI-03: Молодёжная, энергичная цветовая палитра (фиолетовый + бирюзовый + тёмный фон).
- UI-04: Скелетон-загрузка для всех данных.
- UI-05: Информативные пустые состояния.
- UI-06: Понятные сообщения об ошибках.
- UI-07: Навигация: горизонтальная панель (десктоп), таб-бар + бургер (мобильные).
- UI-08: Время отклика UI < 100 мс на взаимодействие.

## 8. Требования к аналитике

- AN-01: Дашборд с виджетами ключевых метрик.
- AN-02: Фильтрация по периоду.
- AN-03: Графики: линейные (динамика), столбчатые (сравнение), круговые (доли).
- AN-04: Детализация по направлениям, ресурсам, пользователям.

## 9. Требования к логированию

- LOG-01: Структурированное логирование (JSON) на бэкенде.
- LOG-02: Уровни: DEBUG, INFO, WARNING, ERROR.
- LOG-03: Request ID для трассировки запросов.
- LOG-04: Ротация логов (по размеру или дате).

## 10. Требования к отчётам и выгрузкам

- REP-01: Excel-выгрузка для: пользователей, бронирований, посещаемости, рейтинга, наград, аналитики.
- REP-02: PDF-отчёты для: сводной аналитики, посещаемости.
- REP-03: Фильтрация по периоду и направлению перед выгрузкой.
- REP-04: Генерация на стороне сервера, скачивание как файл.

## 11. Ограничения

- Платформа работает только на русском языке.
- Одна визуальная тема (без тёмной/светлой переключалки — тема одна, с тёмным фоном).
- Нет интеграции с внешними системами ВУЗа (деканат, БРС) в MVP.
- Нет платёжной системы.
- Нет нативного мобильного приложения (адаптивный веб).
- Серверная инфраструктура — VPS или университетский сервер.
